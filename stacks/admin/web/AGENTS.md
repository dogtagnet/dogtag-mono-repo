## Activity dashboard (PR-D, "see on-chain activity")

The admin portal's oversight surface consuming the PR-B indexer-consumption data layer (`stacks/admin/api`):

- **Activity feed** (`src/pages/Activity.tsx`, nav `/activity`): the UNSCOPED cross-issuer event feed from `GET /v1/admin/activity` (IssuerCreated / RootRegistered / Whitelisted / Delisted / RootIssued / RootRevoked / Verified). Filterable by event type, finality, time range, signer, issuer clone, and record type; each row shows the on-chain time, block + finality, the transaction, the emitting contract, labelled event identifiers, and the signer/clone BUSINESS NAME resolved by the admin directory (`actorName`/`cloneName`). No client PII.
- **Explorer links on the indexer feed are GATED, and must stay gated.** This table renders through the shared `@dogtag/ui` `chain/` primitives (`txExplorerHref`, `addressExplorerHref`, `TxRef`, `ChainValue`, `ProvenanceBadge`), the same ones government Oversight and vet Traceability use. Never link `event.txUrl` directly and never fall back to `explorerTxUrl`, which is what this page used to do: the indexer composes `txUrl` **unconditionally** from `EXPLORER_BASE` (`stacks/indexer/api/src/routes.rs`), so under `INDEXER_DEMO_MODE` its scripted `MemLogSource` events arrive carrying a live-looking `https://explorer.roax.net/tx/0x0800` that addresses nothing on any chain. `txExplorerHref` withholds the link unless `txHash` is a well-formed 32-byte value - arithmetic, not a demo-mode flag, so it still catches ONE synthetic row inside an otherwise-real feed, which a header badge cannot. Same rule for addresses via `addressExplorerHref`.
- **Dashboard** (`src/pages/Dashboard.tsx`): registry counts + cross-issuer on-chain aggregates (`GET /v1/admin/activity/stats`) + a chain-health card (indexer watermark from `GET /v1/admin/activity/status` - head vs indexed block, lag, finality source - plus the live authority map from `GET /v1/admin/governance/authority`) + a recent-activity slice linking to `/activity`.
- **Event presentation helpers** live in `src/lib/activity.ts` (`EVENT_META`, `relativeTime`, `absoluteTime`). `relativeTime`/`absoluteTime` now serve the Dashboard's recent-activity slice only; the Activity table uses `ChainTime`, which leads with the absolute time **and its timezone** (a relative time alone is not something an auditor can cite, and the tooltip that used to carry the absolute form survives neither a screenshot nor a touch device).
- **`shortAddr` (`src/lib/format.ts`) is a MIDDLE-truncator and is guarded by `isOpaqueIdentifier`.** Only ever hand it an address, a hash or a decimal field element. Applied to a human label a middle-truncator reads as corruption rather than elision - in PR #88 the shared truncator rendered `TRAVEL_CLEARANCE` as `TRAVEL_C…ARANCE` on the very cell an operator uses to tell what a row is about. The guard returns human text whole (CSS `truncate` then clips it) so that failure mode cannot reappear here.
- **Wire types + client methods** are in the shared package: `packages/ui/src/api/types.ts` (`ActivityEvent`, `ActivityStats`, `IndexerStatus`, `GovernanceAuthority`, …) and `packages/ui/src/api/central.ts` (`getActivity`, `getActivityStats`, `getActivityStatus`, `getActivityIssuers`, `getDirectory`, `getGovernanceAuthority`).
- **Backend note:** PR-B added the `OversightFeed::status()` method but wired no route; PR-D added the thin `GET /v1/admin/activity/status` proxy (`stacks/admin/api/src/routes.rs`) to surface the chain-health watermark. All activity/count surfaces return **503** (`indexer: not-configured`) when `INDEXER_API_BASE` is unset - the UI renders a first-class "indexer not connected" state, and the registry counts keep working.
- **Verify locally:** `pnpm --filter @dogtag/admin-web build` (tsc + vite) and `cargo test --test indexer_consume` in `stacks/admin/api`. There is no frontend lint/test script - `tsc --noEmit` (the `build`/`typecheck` scripts) is the gate.
